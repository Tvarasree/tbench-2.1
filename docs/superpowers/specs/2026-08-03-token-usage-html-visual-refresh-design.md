# Terminal-Bench Token Usage HTML Visual Refresh

## Goal

Upgrade `token_usage.html` to a richer, self-contained dashboard inspired by the
SWE Auto Eval token report, without changing metric calculation, report schemas,
or benchmark execution.

## Scope

Only the HTML presentation generated by `analysis/token_usage.py` changes.
JSON, CSV, Markdown, Harbor execution, result aggregation, pricing behavior, and
the priced-only HTML emission rule remain unchanged.

## Metric preservation contract

The refreshed report must preserve every existing Terminal-Bench metric,
including:

- total input, cache-read, cache-write, output, and combined tokens;
- billed and custom-priced costs;
- tasks solved and all measured-run tokens/cost per solved task, including failed
  retries;
- winning-attempt-only tokens and cost per solved task;
- successful trial count, measured-successful trial count, priceable-successful
  trial count, successful-trial token total and average, and successful-trial cost
  total and average;
- spend and tokens attributable to a solve, waste totals, and waste percentage;
- measurement coverage and measurement-quality counts;
- outcome, attempt-round, and per-task breakdowns.

No metric may be renamed, removed, recomputed, or silently replaced in the
underlying report dictionary.

## Presentation

The output remains a single offline HTML file with inline CSS and no JavaScript,
fonts, external assets, or network requests. It supports responsive layouts and
the operating system's light/dark preference.

The page contains:

1. A header with run, agent, model, attempt count, generation time, and pricing
   note.
2. A hero metric showing retry-inclusive cost per solved task, with the token
   equivalent and total-run context.
3. KPI cards for total tokens, priced cost, solved tasks, and measurement
   coverage. Token composition remains visible rather than collapsing all token
   types into one opaque total.
4. A highlighted success-economics comparison showing:
   - retry-inclusive cost/tokens per solved task;
   - winning-attempt-only cost/tokens per solved task;
   - average cost/tokens per successful trial, with measured and priceable
     coverage counts.
5. A colored stacked bar and exact table for token usage by outcome.
6. Horizontal comparison bars and an exact table for attempt-round economics.
7. A waste section showing attributable and wasted tokens/cost.
8. The existing per-task table.
9. Methodology and caveats explaining lower-bound telemetry and user-supplied
   pricing.

Bars are normalized within their section. Exact values always remain available
in adjacent labels or tables, so visualization never becomes the only source of
data.

## Defensive behavior

- HTML-escape all metadata, task names, outcome names, and other artifact-derived
  labels.
- A zero maximum produces zero-width bars instead of division by zero.
- Missing costs render as an em dash, not `$0`.
- Missing successful-trial telemetry remains missing and is not averaged as zero.
- Incomplete measurement coverage retains a prominent lower-bound warning.
- Very small stacked-bar segments remain represented in the legend even when an
  inline label would not fit.

## Verification

Emitter tests will assert that:

- all three success-economics representations appear in HTML;
- successful-trial coverage counts and cache-token metrics remain present;
- outcome and round bars are emitted;
- missing costs and zero-valued sections render without exceptions;
- artifact-derived strings are escaped;
- existing JSON, CSV, and Markdown tests continue to pass.

A representative priced synthetic report will be generated and inspected for
valid structure after the complete analysis test suite and syntax checks pass.
